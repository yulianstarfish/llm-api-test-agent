# 常见接口缺陷案例库

以下十个案例均提炼自真实项目，可用于指导测试用例设计，也可在失败归因时作为比对依据。

## 案例1：必填字段缺失返回 500

- 现象：注册接口不传 password，服务端返回 500 Internal Server Error，响应体是语言运行时堆栈。
- 原因：业务代码未做必填校验，空指针或 KeyError 异常未被捕获。
- 测试点：每个必填字段分别缺失一次，期望返回 400 与明确错误码，而不是 500。

## 案例2：越界数值被接受

- 现象：年龄字段传 999 或 -5，接口返回 200 并写入数据库。
- 原因：只在前端表单做了校验，服务端漏掉范围校验。
- 测试点：下界-1、上界+1、负数、超大数各设计一条用例。

## 案例3：重复注册返回 200

- 现象：同一用户名连续注册两次，第二次仍返回 200，数据库出现重复记录或旧记录被静默覆盖。
- 原因：未校验用户名唯一性、未配置唯一索引，且状态码未按文档约定返回 409。
- 测试点：先成功注册，再用相同用户名注册，期望 409 及唯一性错误码。

## 案例4：错误的状态码

- 现象：登录密码错误返回 200，仅靠响应体中的 code 字段表达失败。
- 原因：开发习惯所有响应都用 200，语义全靠 body 表达，与接口文档和 RESTful 约定不符。
- 测试点：断言 HTTP 状态码本身，而不是只看响应体。

## 案例5：敏感信息泄露

- 现象：查询用户接口的响应中包含密码哈希、手机号、身份证号等全量字段。
- 原因：直接序列化数据库实体返回，未使用脱敏 DTO。
- 测试点：按响应字段白名单断言，检查不包含 password、secret、idcard 等敏感字段。

## 案例6：SQL 注入导致全表查询

- 现象：搜索关键词传 `' or '1'='1`，返回了全部用户数据。
- 原因：字符串拼接 SQL，未使用参数化查询。
- 测试点：注入特征串用例，期望返回空结果或 400，且不泄露堆栈与 SQL 片段。

## 案例7：超长字符串撑爆数据库

- 现象：昵称传十万字符，接口 500，日志报 Data too long for column。
- 原因：服务端未限制长度，异常穿透到数据库层才暴露。
- 测试点：上限+1 与极大长度用例，期望 400 友好提示。

## 案例8：分页参数溢出

- 现象：page_size 传 100000，接口把整表加载进内存导致服务 OOM 重启。
- 原因：未限制 page_size 上限。
- 测试点：page_size 取 0、负数、超大值用例，期望被钳制或拒绝。

## 案例9：幂等失效造成重复下单

- 现象：网络重试导致同一订单被创建两次，库存扣了两次。
- 原因：缺少幂等键或防重 token，也未建唯一约束。
- 测试点：相同请求连续或并发发送两次，断言只产生一条记录。

## 案例10：错误提示泄露内部信息

- 现象：参数错误时响应包含 "/opt/app/config.py line 88" 等服务器路径与堆栈。
- 原因：全局异常处理直接把异常对象字符串化后返回给客户端。
- 测试点：触发任意 400/500，断言响应体不含文件路径、类名与 SQL 片段。

## 用法说明

生成用例时可对照以上案例检查覆盖度；对执行失败的用例进行归因时，可将失败现象与案例库比对，快速判断属于需求理解错误、接口缺陷还是用例本身错误。
