# 场景与异常测试

## 基本流与备选流

场景法从业务流程的角度设计测试用例。每个业务流程由一条基本流（Basic Flow）和若干备选流（Alternative Flow）组成：

- 基本流：业务最常用、一切顺利的主路径，例如"注册成功 → 登录成功 → 查询到用户信息"。
- 备选流：在特定条件下触发的分支或异常路径，例如"用户名已存在导致注册失败""密码错误导致登录失败"。

设计步骤：画出业务流程图 → 标出所有判断节点 → 每条从起点到终点的路径即一个场景 → 为每个场景设计至少一条用例。基本流保证主功能可用，备选流保证分支与异常处理被覆盖，二者缺一不可。

## 异常场景清单

接口测试中应系统性地枚举以下异常场景：

1. 空值与缺省：必填字段传 null、空字符串，或整个字段缺失。期望返回 400 类错误而不是 500。
2. 超长输入：字符串长度超过上限 1 位，以及远超上限（如十倍长度），检验服务端是否统一做长度校验。
3. 非法类型：字符串字段传数字、布尔、数组或对象，数字字段传字符串，观察是被框架以 422 拦截还是被业务代码妥善处理。
4. 非法格式：手机号 12 位、邮箱缺少 @、日期出现 "2024-13-45" 等。
5. 重复提交：同一请求在短时间内发送两次（双击、网络重试、刷新重发）。注册、下单、支付类接口必须保证幂等或有唯一约束。
6. SQL 注入字符串：`' or 1=1 --`、`'; drop table users;--` 等，期望被参数化查询安全处理，返回正常错误提示而非堆栈或全表数据。
7. XSS 脚本字符串：`<script>alert(1)</script>`，检验是否安全存储并在展示时转义。
8. 越权场景：用普通用户凭证访问管理员接口，或修改 URL 中的 id 访问他人数据（水平越权）。
9. 并发场景：多个请求同时使用同一用户名注册、对同一库存并发扣减，检验唯一约束与锁机制。
10. 边界外数值：负数金额、超过 int64 的超大整数、科学计数法字符串等。

## 示例：注册接口场景设计

- 基本流：合法用户名 + 合法密码 → 注册成功（HTTP 200）。
- 备选流 1：用户名已存在 → 期望 HTTP 409 与明确的业务错误码。
- 备选流 2：密码长度不合法 → 期望 HTTP 400。
- 异常场景：连续提交两次完全相同的注册请求，第二次必须被拒绝且不能产生两条用户记录；username 传 `' or 1=1 --` 应被安全拒绝；并发发送 10 个相同注册请求只允许一个成功。

## 设计要点

异常用例的"期望结果"必须依据需求文档明确写出，而不是"不崩溃即可"。只有把期望状态码、业务错误码、错误信息结构都断言清楚，异常场景测试才真正具备缺陷检出能力，否则即便接口行为错误，用例也可能误报通过。
